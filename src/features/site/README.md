# 공개 사업장 홈 (에픽 #10) — 설계 기록

정본은 `majubom-docs/02_기능명세서.md` FR-SITE-010. 명세가 정하지 않은 것을 여기서 어떻게 정했는지만 적는다.
지금 있는 것은 **시작 템플릿 렌더(#72) · 섹션(#73) · 상태별 404(#74) · SEO(#75) · 밝기(#76) · 모바일(#77)** 이다.

```
features/site/routing.ts       /@{slug} ↔ /site/{slug} 주소 규칙. 순수
features/site/public-home.ts   데이터 + 공개 여부 판정 (이 에픽의 게이트가 여기 하나)
features/site/revalidate.ts    콘솔이 뭔가 바꿨을 때 경로 무효화
features/site/theme.ts         밝기 규칙 · 첫 페인트 전 스크립트. 순수
features/site/theme-settings.ts 사업자가 고른 밝기의 저장 (읽기는 public-home 이 같이 가져간다)
features/site/ui/hours.ts      영업시간 문구. 순수
features/site/ui/PublicHome.tsx 시작 템플릿
app/site/[slug]/page.tsx       내부 경로. 손님이 보는 주소는 /@{slug}
```

## 결정한 것

**주소는 `/@{slug}`, 렌더는 `/site/{slug}`.** 최상위에 `app/[handle]` 을 두면 정의되지 않은 **모든** 최상위 경로를
그 라우트가 삼킨다. 정적 라우트가 우선이라 `/login` 은 멀쩡하지만, 그 뒤로 생기는 모든 경로가 이 파일의 관심사가 된다 —
실제로 `no-html-link-for-pages` 가 `/console` 을 "내부 페이지" 로 새로 인식할 만큼 넓었다.
프록시가 rewrite 하고, `/site/…` 를 직접 치면 404 다. 같은 내용이 두 주소로 열리면 색인이 갈린다.
rewrite 대상 slug 는 `^[a-z0-9-]{3,30}$` 로 검사한다 — 안 하면 `new URL("/site/../admin")` 이 `/admin` 으로 정규화된다.

**빌더 없이도 공개된다.** 승인된 사업장에는 시작 템플릿이 적용돼 "빌더를 한 번도 열지 않아도 즉시 예약을 받을 수 있다"(기획서).
그래서 `site_pages` 행이 **없으면 공개**로 본다(`publish-gate.ts` 의 기본값도 같이 뒤집었다). 행이 있고 `is_published = false` 면
사업자가 명시적으로 내린 것이니 따른다. 빌더(에픽 #15)가 오면 `published_data` 가 이 템플릿을 대체한다.

**볼 수 없는 것은 전부 같은 404 다.** 없는 slug · 승인 전 · 정지 · 차단 · 내려둔 홈 · 팔 것이 없는 가게 ·
정보가 덜 찬 가게가 모두 `null` 이다. 상태마다 다른 응답을 주면 slug 를 훑어 사업장 목록을 만들 수 있다.
**옮겨 간 옛 주소의 301 도 이 규칙을 탄다** — 목적지가 지금 열려 있을 때만 알려 준다. 아니면 "이 이름은 임자가 있고 지금 주소는 이것"
이 정지된 사업장에 대해서도 새어 나간다.

**정보 완성도(`isInfoComplete`)까지 공개 조건이다.** 콘솔은 그 조건으로 "아직 공개 아님" 이라고 말하는데 홈만 따로 열리면,
사장님은 비공개인 줄 아는 사이 임시 주소(`b-xxxxxxx`)가 상호와 소개를 내보낸다. 한 번 쓴 slug 는 영구 예약이라 되물릴 수도 없다.

**휴무 메모는 공개하지 않는다.** 콘솔의 그 칸은 "예: 추석 연휴, 직원 교육" 이라고 안내하는 내부 메모다 —
손님에게 보이는 줄 모르고 "원장 병원 진료" 같은 것을 적는다. 날짜와 부분 휴무 시간만 내보낸다.

**JSON-LD 는 이스케이프해서 심는다.** `JSON.stringify` 는 `<` 를 건드리지 않으므로 그대로 넣으면 사업자가 소개글에
`</script><script>…` 를 쓰는 것만으로 손님 브라우저에서 스크립트가 돈다. 상호·소개·주소는 전부 자유 입력이고 CSP 에 `script-src` 도 없다.

**캐시는 두 겹이고, 안 거는 경우가 둘 있다.** `revalidate = 60` 은 Next 의 것이고 App Hosting 은 Cloud Run 위라 인스턴스마다 따로다 —
실질 캐시는 CDN 이라 프록시가 `s-maxage=60` 을 싣는다. 다만 응답이 **쿠키를 심을 때**(세션 갱신분이 캐시를 타면 남의 세션이 배달된다)와
**1기 Basic Auth 가 켜져 있을 때**(`public` 은 RFC 9111 §3.5 의 "Authorization 요청은 캐시 금지" 를 푸는 지시어다 —
한 번 통과한 응답이 인증 없는 요청에 그대로 나가 미리보기 게이트가 통째로 뚫린다)는 `private, no-store` 다.

**무효화는 내부 경로로 한다.** Next 가 캐시하는 것은 rewrite 뒤의 `/site/{slug}` 라 `/@…` 를 지우면 아무것도 안 지워진다.
주소를 바꿀 때는 **옛 경로도** 지운다 — 거기 남은 캐시가 301 대신 옛 페이지를 계속 내보낸다.
지우는 것은 Next 의 캐시뿐이라 CDN 은 최대 60초 옛 화면을 들고 있다. CDN 퍼지는 2기(에픽 #20).

**지도는 링크다.** `map.kakao.com/link/…` 은 카카오맵을 여는 주소지 임베드 엔드포인트가 아니라 프레임이 거부된다 —
iframe 으로 넣으면 조용히 빈 상자가 남는다. JS SDK 로 심으려면 appkey 와 좌표 입력 UI 가 필요하고, 그건 #12(주소 검색)와 함께 온다.

**밝기는 세 겹이고, 손님이 마지막 말을 한다.** 아무것도 없으면 라이트, 사업자가 고르면 그것(AUTO 는 손님 OS 설정),
손님이 헤더 토글을 누르면 그것이다. 사업자 선택을 손님이 덮는 것은 일부러다 — 밝기는 취향이 아니라 눈의 문제고,
그래서 토글이 헤더에 있다. 손님 쪽 열쇠는 `site-theme` 으로 콘솔(`theme`)과 **다르다**: 같이 쓰면 사장님이 콘솔을
어둡게 해 둔 것이 자기 가게 홈을 어둡게 만들고, 손님이 남의 가게에서 누른 것이 우리 콘솔을 바꾼다.

**밝기는 인라인 스크립트로 건다.** `<html>` 은 루트 레이아웃 것이라 이 페이지가 서버에서 속성을 못 박는다.
감싸는 div 에 `data-theme` 를 걸면 토큰은 바뀌지만 `body` 배경은 루트 값 그대로라 스크롤 끝에서 반대 색이 비친다.
그래서 본문보다 앞선 인라인 스크립트가 파싱 중에(= 페인트 전) `<html>` 에 직접 건다. `removeAttribute` 가 있는 이유는
루트 레이아웃의 콘솔용 초기화가 먼저 돌아 값을 이미 박아 뒀을 수 있어서다 — AUTO 는 그것까지 걷어내야 OS 설정이 산다.

**밝기는 `site_pages.theme` 에 산다. 행을 만들 때 `is_published` 는 반드시 true 다.**
공개 여부 판정이 `coalesce(sp.is_published, true)` 라, 컬럼 기본값(false)에 맡기고 행을 만들면
"다크로 바꿔 볼까" 한 순간 가게가 조용히 404 가 된다. `tests/db/site-theme.test.ts` 가 이 한 줄을 지킨다.
밝기를 businesses 컬럼으로 빼지 않은 이유는 빌더(에픽 #15)가 `theme` 을 통째로 가져갈 자리이기 때문이다.

**폰 화면은 상·하 두 줄이 잡아 준다 (#77).** 위는 상호와 밝기 토글이 붙은 sticky 줄 — 커버 사진 위에 투명하게
띄우면 밝은 사진에서 글자가 사라진다. 아래는 폰에서만 뜨는 전화·길찾기 바다. **예약 버튼은 아직 없다** —
위젯이 에픽 #11 이라, 지금 넣으면 죽은 버튼이다. 넓은 화면에서는 본문에 같은 링크가 있어 하단 바를 숨긴다.

**`generateMetadata` 와 본문이 같은 데이터를 쓴다.** drizzle 은 Next 의 요청 단위 중복 제거를 못 타므로
`resolveSlug`·`loadPublicHome` 을 `react` 의 `cache()` 로 감쌌다. 안 감싸면 한 요청에 쿼리가 통째로 두 번 돈다.
